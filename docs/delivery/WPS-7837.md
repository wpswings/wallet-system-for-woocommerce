## What was built
A self-contained Playwright E2E test suite under `tests-e2e/`, independent of the
plugin's own build tooling (separate `package.json`/`node_modules`, avoiding a
pre-existing React 17/18 peer conflict in the plugin's `@wordpress/scripts` setup).
It drives the real plugin against the live local WordPress/WooCommerce site — no
mocking — covering admin settings, wallet management, the full customer-facing
wallet dashboard, checkout integration, and automatic wallet-crediting rules.

## How it works
- `playwright.config.js` defines two projects: `setup` (runs once — creates two
  dedicated test customer accounts, logs in as admin + each customer, and drives the
  real Settings UI to turn on every feature toggle the suite exercises since most are
  off by default on a fresh install) and `chromium` (the actual specs).
- `wp-tool/index.php` + `scripts/wp-bootstrap-exec.sh` boot the site's real
  `wp-load.php` (via Local by Flywheel's own PHP binary/ini, since there's no
  `wp-cli` and system PHP doesn't know the site's non-default MySQL socket) to do
  setup/teardown and DB-level assertions through WordPress's own APIs.
- `fixtures/` hold reusable helpers: admin settings-tab navigation & save,
  checkout (this store uses the React-based WooCommerce Cart & Checkout Blocks, not
  classic shortcode checkout), order status/refund actions, and a Mailpit client
  (Local intercepts this site's outgoing mail) for asserting notification emails.

## Inputs
- Local site at `http://localhost:10130` (WooCommerce + this plugin active).
- Admin credentials, `WPS_E2E_ADMIN_USER`/`WPS_E2E_ADMIN_PASS` (see `config.js`).

## Testing
- Tested locally: Yes — full suite run repeatedly to green: **53/53 tests passing**.
- Edge cases covered:
  - Wallet Payment gateway hidden when balance < order total, offered once it covers it.
  - Partial payment (manual wallet amount + Apply) reduces the payable total.
  - Cashback granted on order completion, clawed back on cancellation.
  - Transfer rejected when exceeding balance or targeting self (client-side disabled button).
  - Daily-visit bonus fires once per day, not twice.
  - Recharge order does not credit until admin marks it Completed.
  - Refund-to-wallet via the plugin's own admin refund button.
  - REST API auth (wrong consumer key/secret rejected).
